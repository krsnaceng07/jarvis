JARVIS Architecture Overview

OpenClaw-inspired multi-package AI assistant architecture

JARVIS is a local AI assistant built as a modular Python workspace. It combines apps, runtime logic, model providers, plugins, memory, and skills into one system.

1. Main Layers

  • Apps: desktop HUD, CLI, TUI
  • Core packages: plugin_sdk, agent_runtime, llm_client, gateway_protocol, config_core, memory_host_sdk, channels_core, etc.
  • Extensions: channels, providers, media, memory, tools, voice, productivity, infrastructure
  • Skills: declarative markdown skill files under skills/
  • Support systems: docs, tools, security, qa, deploy, examples

2. Architecture Rule

Core is intentionally plugin-agnostic. Extensions interact with core via jarvis_sdk.*, not via ad-hoc imports. This keeps the platform modular, safe, and easier to scale.

3. Runtime Workflow

User request → app/channel → gateway/runtime → model/provider → tools/plugins → memory/state → response

In practical terms: a user input enters an app, the runtime chooses the correct skill or tool, invokes the model or provider, persists needed state, and returns a final response.

4. Storage and Config

JARVIS prefers canonical, schema-based storage, with SQLite as the default for runtime state and memory-related data. Migration and repair logic is handled through doctor/repair flows rather than runtime compatibility hacks.

5. Why This Design Matters

  • Better separation of concerns
  • Safer extension boundaries
  • Cleaner memory and state management
  • Scalable addition of providers and channels
  • Strong foundation for a personal AI assistant ecosystem

6. Summary

JARVIS is not a single monolithic script. It is a structured AI assistant platform with apps, a plugin runtime, provider integrations, task execution, memory, and skills layered together.
