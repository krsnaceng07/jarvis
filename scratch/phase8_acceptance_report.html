Phase 8: Technical Hardening Architecture & Immediate Actions
Reference: INV-SHD-001 to INV-ART-002

Key Technical Hardening Architecture

1. Cryptographically Bound Operator Approval Token (INV-AUTH-001)

Operator promotion authorization tokens bind human identity, execution context, and cryptographic digests:

OperatorApprovalToken(
    operator_identity="operator_alice",
    operator_os_sid="S-1-5-21-3623811015-3361044348-30300820-1013",
    session_id="sess_auth_987",
    operator_role="learning_admin",
    model_id="cand_v100",
    artifact_digest="sha256_art_...",
    checkpoint_digest="sha256_ckp_...",
    evaluation_report_digest="sha256_rep_...",
    runtime_contract_digest="sha256_contract_...",
    approval_nonce="nonce_single_use_456",
    approval_timestamp=1789665000.0,
    expiry_timestamp=1789668600.0,
    token_signature="hmac_sha256(...)"
)
2. Measured Service-Level Objectives for Shadow Dispatch (INV-SHD-004)

Universal absolute latency claims replaced by measured statistical SLO distributions:

  • Shadow Dispatch Overhead: p50 ≤ 1.0ms, p95 ≤ 5.0ms, p99 ≤ 20.0ms hard ceiling.
  • Active-Path Added Latency: ≤ 1.0ms maximum allowable overhead.
  • Zero Active Request Blocking: On queue saturation, shadow requests shed non-blockingly without delaying active turns.
3. Explicit 7-Tier Data Sensitivity Classification (INV-PRIV-001)

Granular classification ensures even read-only observations cannot leak sensitive user activity:

  • PUBLIC_READ_ONLY: Time, volume, window title (safe for shadow read).
  • SENSITIVE_READ_ONLY: Browser tabs, app state, clipboard (sanitized snapshot only).
  • PRIVILEGED_READ_ONLY: Browser cookies, credentials, private keys (strictly denied in shadow).
  • SIMULATABLE: Focus window, switch tab, set volume (dry-run simulated state).
  • SIDE_EFFECTING: WhatsApp, delete file, write file, execute shell (intercepted, never executed).
  • FORBIDDEN: Direct socket writes, process injection (hard blocked at gateway boundary).
  • REDACTED / UNAVAILABLE: Stripped tokens and masked credentials.
4. Stale-Result Protection & Task Generation Tracking (INV-VOICE-001, INV-CORR-001)

Every active turn carries conversation_id, turn_id, task_generation, cancellation_token, and state_version:

  • Barge-in voice cancellation terminates pending execution within 150ms.
  • Commit guards abort stale commits if cancellation token was signaled before state mutation.
  • User corrections bump task_generation; actions belonging to older generations are discarded immediately.
5. Strict Fallback Metric Schema Isolation (INV-SHD-002)

Metric schema explicitly separates candidate performance from safety fallbacks:

  • candidate_direct_success: Evaluated solely on turns where candidate executed directly.
  • fallback_success: Turns completed by fallback LLMs are strictly excluded from candidate accuracy.
